When a trade goes wrong — the buyer says they paid but the seller won't release, or the payment never arrived — either party can open a dispute. An arbiter is assigned, both parties submit evidence, and the arbiter issues a ruling that the node only executes after verifying the arbiter's own signature over it.

## How a dispute runs

1. **Open** — a party disputes the escrow. The escrow moves to `DISPUTED` and an arbiter is assigned.

2. **Evidence** — both parties attach evidence while the dispute is `OPENED` or `EVIDENCE_SUBMITTED`.

3. **Automated proposal (optional)** — if the node enables it, on-device AI (QVAC) may propose a ruling (`AUTO_PROPOSED`). It's **advisory only**: it never moves funds by itself.

4. **Signed ruling** — the assigned arbiter signs a `RELEASE`, `REFUND`, or `SPLIT` decision with their own key. The node verifies the signature, then settles.

5. **Appeal (market arbitration)** — a party can reopen a resolved dispute for a larger, reputation-weighted panel.

<Note>
  Arbitration needs arbiters. With the default (trusted) arbitration mode, the node assigns arbiters from its configured `TRUSTED_ARBITRATORS` list — a fresh local node has none, so disputes can't be resolved until one is configured. Check with your node operator before relying on disputes in production.
</Note>

## Open a dispute

```typescript
const dispute = await buyer.settlement.dispute(
  escrow.id,
  'Paid via PIX 24 hours ago; seller has not released.',
  [{ type: 'payment_receipt', note: 'PIX confirmation E0000…' }], // optional
);
```

You don't need to send the dispute ID to your counterparty — they find it on the escrow (`settlement.get(escrowId)` returns `disputes`).

<Tip>
  Record your payment as soon as you pay: assert a `payment_sent` claim and submit the receipt through [OpenProof](/api/proof). You can then reference stored evidence from the dispute with `evidenceReferenceId`. Evidence reused across different trades is automatically flagged.
</Tip>

## Submit evidence

```typescript
await client.settlement.submitDisputeEvidence(dispute.id, {
  type: 'payment_receipt',
  evidenceReferenceId: storedEvidence.id, // or uri / note
  idempotencyKey: 'receipt-1',            // safe to retry
});
```

Each submission moves the dispute to `EVIDENCE_SUBMITTED`. With automated resolution enabled, it can also trigger a new automated proposal.

## Automated proposals

When QVAC proposes a ruling, the dispute becomes `AUTO_PROPOSED` with an `autoResolutionDeadline` (24 hours by default).

- **Either party can contest it** before the deadline with `contestAutoResolution()`. The dispute returns to `EVIDENCE_SUBMITTED` and the assigned arbiter decides.
- **If nobody contests**, the proposal still doesn't execute. When the deadline passes, the dispute returns to the assigned arbiter, with the proposal's recommendation and reasoning kept as context.

```typescript
await client.settlement.contestAutoResolution(dispute.id);
```

Only a signed decision by the assigned arbiter ever settles a dispute. Automated proposals are off unless the node enables them.

## Arbiter ruling

The assigned arbiter resolves with their wallet. The SDK builds the canonical decision (dispute, escrow, appeal round, arbiter, ruling, split share, and timestamp) and asks the wallet to sign it:

```typescript
await arbiter.settlement.resolveDisputeWithWallet(dispute.id, 'RELEASE', arbiterWallet);

// A split: the buyer's share in basis points (1–9999).
await arbiter.settlement.resolveDisputeWithWallet(dispute.id, 'SPLIT', arbiterWallet, undefined, undefined, 6000);
```

| Ruling | Effect | Escrow ends as |
| --- | --- | --- |
| `RELEASE` | Pays the buyer's registered payout address | `COMPLETED` |
| `REFUND` | Pays the seller's registered payout address | `REFUNDED` |
| `SPLIT` | Divides the funds by `splitBuyerBps` (`MOCK`, `WDK_USDT_EVM`, `MULTISIG`) | `SPLIT` |

A ruling without a valid signature from the assigned arbiter's registered key is rejected with `403`. For client-held-key escrows, the ruling starts a signing round in which the arbiter's key is already applied, so one party's signature completes it.

## Appeal

```typescript
const { dispute: appealed, appealFeeRequired } = await client.settlement.appealDispute(dispute.id);
```

Appeals exist only when the node runs `ARBITRATION_MODE=market`. They reopen a `RESOLVED` dispute (`APPEALED`) for a larger, reputation-weighted panel. The appeal fee is refunded or forfeited once the panel rules. In market mode, anyone can become an arbiter by registering collateral with `arbitration.register()`.

## Expired escrows

If a client-held-key escrow reaches `EXPIRED` (its timelock passed before the buyer paid), the seller — the only party with funds at stake — recovers them through arbitration:

```typescript
const recovery = await seller.settlement.initiateExpiryRecovery(escrow.id);
```

## Status reference

| Status | Meaning |
| --- | --- |
| `OPENED` | Dispute raised; evidence window open |
| `EVIDENCE_SUBMITTED` | At least one party submitted evidence |
| `AUTO_PROPOSED` | An automated proposal is waiting; contest window open |
| `ARBITRATED` | An arbiter reviewed the case |
| `RESOLVED` | A signed ruling was executed |
| `APPEALED` | A resolved dispute was reopened for an appeal panel |

The durable record of a ruling is available to the trade's parties with `settlement.getSemanticRecord(disputeId, appealRound)`.
