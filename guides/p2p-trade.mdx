In production, seller and buyer are different users in different apps, each with their own `SailsClient`, identity, and session. They coordinate only through shared IDs (`offer.id`, `trade.id`, `escrow.id`) and the trade channel. This guide shows what each side does, in order.

<Note>
  Custody depends on the settlement provider: client-held-key providers (`MULTISIG`, `LIGHTNING_HODL`, `SAFE_GUARD_EVM`) keep buyer and seller keys on their devices, while `WDK_USDT_EVM` is server-custodial and `MOCK` moves no real funds. See [Escrow Lifecycle](/guides/escrow-lifecycle) before choosing one.
</Note>

## 0. Both parties: set up

```typescript
const client = new SailsClient({ baseUrl: process.env.SAILS_BASE_URL! });

const { participant, keypair } = await client.identity.create(undefined, 'Alice');
await client.identity.authenticate(keypair);

// Production nodes enforce capability grants — idempotent, run it on every login.
await client.capabilities.ensureCanonicalGrants(participant.id);

// Releases, refunds, and rulings pay your registered address for the asset.
await client.settlement.setPayoutAddress({ asset: 'BTC', address: myBtcAddress });
```

## 1. Seller: publish an offer

```typescript
const offer = await seller.liquidity.publish({
  asset: 'BTC',
  side: 'SELL',
  priceUsd: '65000',
  minAmount: '0.001',
  maxAmount: '0.05',
  paymentMethod: 'PIX',
  paymentDetails: 'seller-pix-key', // never exposed by public offer endpoints
  idempotencyKey: 'offer-2026-09-21-1',
});
```

## 2. Buyer: find an offer and open a trade

```typescript
const { offers } = await buyer.liquidity.discover({ asset: 'BTC', side: 'SELL', paymentMethod: 'PIX' });
const chosen = offers[0];

// Check the counterparty before trading.
const detail = await buyer.liquidity.getOffer(chosen.id);
const trust = await buyer.reputation.get(detail.user.id);

const trade = await buyer.openp2p.trade(chosen.id, '0.01');
```

Prefer to describe what you want in plain language? See [AI Agents](/guides/ai-agents) for intent drafts and `proposeTrade()`.

## 3. Both: agree on the details in the trade channel

```typescript
const channel = client.openp2p.chat(trade.id);
channel.onMessage((msg) => render(msg));
channel.onEvent((frame) => {
  if (frame.type === 'ESCROW_STATUS_UPDATE') refreshEscrow();
  if (frame.type === 'RISK_WARNING') showWarning(frame.payload);
});
channel.send({ content: 'Ready — please share payment details.' });
```

The channel reconnects automatically; after a long disconnection, catch up with `openp2p.reconcileTrade(trade.id, lastSeenAt)`.

## 4. Seller: create and fund the escrow

```typescript
const escrow = await seller.settlement.create({ tradeId: trade.id, lockedAmount: '0.01', asset: 'BTC' });
```

For client-held-key providers, both parties submit an escrow key (`submitKey`), the seller funds the deposit address on-chain, then locks. See [Escrow Lifecycle](/guides/escrow-lifecycle#client-held-keys-multisig).

```typescript
await seller.settlement.lock(escrow.id);
```

## 5. Buyer: pay off-chain and record it

Pay the seller outside the protocol (PIX, bank transfer, …). Then record proof and mark the payment sent:

```typescript
const claim = await buyer.proof.assertClaim({
  claimType: 'payment_sent',
  assertion: { method: 'PIX', amount: '3500.00', currency: 'BRL' },
  tradeId: trade.id,
});
await buyer.proof.submitProof({ claimId: claim.id, evidence: { endToEndId: 'E0000…' } });

await buyer.settlement.markPaymentSent(escrow.id);
```

## 6. Seller: confirm receipt and release

Direct-call providers:

```typescript
await seller.settlement.release(escrow.id); // pays the buyer's registered address
```

Client-held-key providers run a signing round instead: `initiateRelease()`, then each required signer calls `submitTransactionSignature()` with their own signature. `complete: true` means the release transaction was broadcast.

## 7. Both: rate the trade

```typescript
await buyer.reputation.rate({ tradeId: trade.id, ratedId: sellerId, score: 5 });
```

Ratings are informational; the trust score comes from settlement outcomes.

## If something goes wrong

- **Before funds are locked:** cancel by agreement with `openp2p.updateTradeStatus(trade.id, 'CANCELLED')` — always a neutral reputation outcome.
- **After funds are locked:** open a dispute with `settlement.dispute(escrow.id, reason, evidence)`. See [Disputes](/guides/disputes).
