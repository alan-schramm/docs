Sails integrates QVAC — Tether's local AI runtime — for AI-assisted trading. Inference runs on the Sails node with a small local model (Llama 3.2 1B, llama.cpp); no cloud AI provider is involved.

## What the AI does — and doesn't

| Does | How |
| --- | --- |
| Draft a structured trade intent from a goal | `agents.generateTradeIntent(goal)` — one model call |
| Draft a structured offer from a goal | `agents.generateOfferIntent(goal)` — one model call |
| Assess the risk of an intent's shape | `agents.assessIntentRisk(intent)` — one model call |
| Flag possible social engineering in trade chat | `RISK_WARNING` events, when the node enables it |
| Propose an advisory dispute ruling | Only when the node enables it — never executes on its own (see [Disputes](/guides/disputes)) |

It does **not** negotiate with your counterparty, hold state between calls, or act on your behalf. Finding a matching offer for an intent (`proposeTrade`) is deterministic matching against your declared limits, not a model call. Every output is a draft or advice you review.

## Draft a trade intent

```typescript
const draft = await client.agents.generateTradeIntent('Buy 0.01 BTC using PIX, max R$ 3,500');
// { asset: 'BTC', side: 'BUY', maxValue: '3500', minValue: '…', currency: 'BRL', fiatMethod: 'PIX' }

// Review and adjust, then create the intent.
const intent = await client.createIntent('TradeIntent', { ...draft, maxPriceUsd: '66000' });
```

## Find a matching offer for the intent

```typescript
const { proposal, counterProposal } = await client.proposeTradeOutcome(intent.id, '0.01');

if (proposal) {
  // An offer within every limit you declared. Nothing is opened until you approve:
  await client.openp2p.trade(proposal.offerId, '0.01');
} else if (counterProposal) {
  // Only price missed: suggestedPriceUsd is your own declared bound.
  console.log(counterProposal.reasoning);
}
```

`proposeTrade()` returns just the proposal (or `null`). Neither call opens a trade or touches escrow.

## Draft an offer

```typescript
const draftOffer = await client.agents.generateOfferIntent('Sell up to 1 BTC accepting bank transfer');
// { asset: 'BTC', side: 'SELL', minAmount: '0.001', maxAmount: '1', paymentMethod: 'BANK_TRANSFER' }

await client.liquidity.publish({ ...draftOffer, priceUsd: '65000' });
```

## Assess risk

```typescript
const assessment = await client.agents.assessIntentRisk({
  asset: 'BTC', side: 'BUY', maxValue: '500', currency: 'USD', fiatMethod: 'PIX',
});
// { risk: 'low' | 'medium' | 'high', reasoning: '…', recommendation: 'proceed' | 'hold' | 'reject' }
```

The assessment looks only at the intent you pass — not at a counterparty's reputation or history (use `reputation.get()` for that). It's advice from a small local model; it never blocks anything.

## Social-engineering warnings

When the node operator enables detection (`SOCIAL_ENGINEERING_DETECTION=true`), trade chat can carry `RISK_WARNING` events for patterns like requests to move the conversation elsewhere or sudden changes to payment details:

```typescript
const channel = client.openp2p.chat(trade.id);
channel.onEvent((frame) => {
  if (frame.type === 'RISK_WARNING') showWarning(frame.payload);
});
```

Detection only: messages are never blocked, changed, or delayed. Your user decides what to do.

## Availability and limits

Agent calls need a session, and the node must have its local model available. Each call runs real inference, so they share a stricter rate limit. On a `429`, the SDK throws `SailsRateLimitError`; agent calls are `POST` requests, so the SDK never retries them automatically — back off and retry yourself.
