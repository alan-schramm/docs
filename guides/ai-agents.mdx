Sails Protocol's OpenAgents module integrates QVAC — Tether's on-device LLM — for AI-assisted trading. All inference runs locally on your device; no data is sent to external AI providers. This keeps your trading activity private and means the AI works even when you're offline or on a restricted network.

<Note>
  QVAC requires the Sails node to have QVAC configured (`qvac-agent.provider.ts` with a local llama.cpp model). The `agents.*` endpoints return a `SailsNotImplementedError` if QVAC is not available on the node. Check with your node operator before building features that depend on these endpoints.
</Note>

## Generate a Trade Intent from Text

Instead of manually constructing a trade intent payload, describe your goal in plain language and let QVAC produce the structured intent for you. The returned object maps directly onto the parameters `createIntent()` expects.

```typescript
const intent = await client.agents.generateTradeIntent({
  goal: 'I want to buy 0.01 BTC using PIX, max price $46,000',
});
console.log('Generated intent:', intent);
// { side: 'BUY', asset: 'BTC', amount: '0.01', maxPriceUsd: '46000', paymentMethod: 'PIX' }

// Use the generated payload directly
const created = await client.createIntent('TradeIntent', intent);
```

QVAC parses the natural-language goal and outputs a `GeneratedTradeIntent` with fields for `asset`, `side`, `maxValue`, `minValue`, `currency`, and `fiatMethod`. You can inspect and edit the output before passing it to `createIntent()` — treat the AI output as a helpful starting point, not a binding action.

## Generate an Offer Intent

Sellers can use the same approach to describe an offer in plain language. QVAC returns a `GeneratedOfferIntent` ready to pass to `liquidity.publish()`.

```typescript
const offerIntent = await client.agents.generateOfferIntent({
  goal: 'Sell up to 1 BTC at market rate, accepting bank transfer',
});
```

The response includes fields for `asset`, `side`, `minAmount`, `maxAmount`, and `paymentMethod` — the same shape `liquidity.publish()` accepts.

## Risk Assessment

Before executing a trade with an unfamiliar counterparty, run the intent through QVAC's risk assessment. This produces a human-readable evaluation with a risk level, reasoning, and a specific recommendation — entirely on-device, with no data leaving your machine.

```typescript
const assessment = await client.agents.assessIntentRisk(intent);
console.log('Risk level:', assessment.risk);         // LOW | MEDIUM | HIGH
console.log('Reasoning:', assessment.reasoning);
console.log('Recommendation:', assessment.recommendation);
```

<Tip>
  Use `agents.assessIntentRisk()` before executing any trade with a new counterparty. A `HIGH` risk assessment doesn't automatically block anything — the recommendation is advisory, and you decide whether to proceed.
</Tip>

The risk assessment reads the same intent fields you'd pass to `createIntent()`. You can call it before committing to a trade, making it a lightweight pre-flight check that costs nothing beyond the local inference time.

## Social Engineering Detection

QVAC can monitor the negotiation chat channel for known fraud patterns — unexpected requests to move communication off-platform, last-minute payment instruction changes, urgency manipulation, and other configurable signals. This feature is off by default and must be enabled by the node operator (`SOCIAL_ENGINEERING_DETECTION=true`).

When enabled, the WebSocket channel emits `RISK_WARNING` events alongside normal chat messages. Subscribe to these events in your channel handler:

```typescript
const channel = client.openp2p.chat(trade.id);
channel.onEvent((event) => {
  if (event.type === 'RISK_WARNING') {
    console.warn('Potential fraud detected:', event.payload.warning);
  }
});
```

<Note>
  The Social Engineering Agent is detection-only — it never blocks, modifies, or delays a message. It emits a `RISK_WARNING` event that your UI can surface to the user; the user decides how to respond. This design is a protocol invariant: an agent behavior must never act unilaterally.
</Note>

## Agent Rate Limits

All three `agents.*` endpoints require an active session and share the node's critical-tier rate limit because each call runs real local LLM inference — a meaningfully more expensive operation than a standard read or write. If you hit a `429`, catch the `SailsRateLimitError` specifically and back off before retrying:

```typescript
import { SailsRateLimitError } from '@satsails/p2p-trading-sdk';

try {
  const assessment = await client.agents.assessIntentRisk(intent);
} catch (err) {
  if (err instanceof SailsRateLimitError) {
    // Back off and retry after the window resets
    console.warn('Rate limited — back off before retrying agent calls');
  } else {
    throw err;
  }
}
```

Unlike GET requests, mutating calls (including all `agents.*` POST endpoints) are never automatically retried by the SDK — you control the retry logic.
