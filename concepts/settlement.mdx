Settlement in Sails Protocol is handled through pluggable escrow providers. Most providers are non-custodial — Sails never holds the keys needed to move your funds. One disclosed exception: `WDK_USDT_EVM` is a **server-custodial reference implementation** (see below) — a single server-held key can sign its escrows. The escrow type you choose determines how funds are locked, who holds the keys, and how the release is authorized. You pick the provider that matches your asset, your network, and your security requirements.

## Escrow Lifecycle

Every escrow moves through a well-defined state machine. The happy path is linear; disputes branch off from `PAYMENT_PENDING`.

<Steps>
  <Step title="CREATED">
    The escrow record is created after both parties agree on terms during negotiation. No funds have moved yet.
  </Step>
  <Step title="FUNDS_LOCKED">
    The seller locks their digital asset into the escrow. Sails holds no custody — the funds are locked by the escrow contract or multisig output directly.
  </Step>
  <Step title="PAYMENT_PENDING">
    The buyer marks their fiat payment as sent. Fiat always flows directly between participants — the protocol never touches it. The buyer shares a payment receipt as a Proof via the negotiation channel.
  </Step>
  <Step title="COMPLETED">
    The seller confirms receipt and signs the release. The escrowed asset settles to the buyer's address. Both parties' reputation scores are updated from this outcome.
  </Step>
</Steps>

<Accordion title="Dispute branch: DISPUTED → RELEASED or REFUNDED">
  If either party contests the trade at the `PAYMENT_PENDING` stage, the escrow status moves to `DISPUTED`. The Dispute primitive takes over: Policy Engine auto-resolution runs first, then agent-assisted resolution, and finally a Trusted Arbiter if needed. The arbiter issues a ruling — `RELEASE`, `REFUND`, or `SPLIT` — which resolves the dispute back into a terminal Settlement state.
</Accordion>

## Standard Escrow Flow

The four core settlement methods mirror the escrow lifecycle directly. All methods require an active session from `identity.authenticate()`.

```typescript
import { SailsClient } from '@satsails/p2p-trading-sdk';

// Create the escrow after terms are agreed in negotiation
const escrow = await client.settlement.create({
  tradeId: trade.id,
  type: 'MULTISIG',        // omit to let the SDK pick based on asset
  lockedAmount: '0.01',    // decimal string — never a JS number
  asset: 'BTC',
});

// Seller locks funds: CREATED → FUNDS_LOCKED
await client.settlement.lock(escrow.id);

// Buyer marks fiat payment sent: FUNDS_LOCKED → PAYMENT_PENDING
await client.settlement.markPaymentSent(escrow.id);

// Seller confirms receipt and releases funds: PAYMENT_PENDING → COMPLETED
await client.settlement.release(escrow.id, buyerPayoutAddress);
```

If either party needs to raise a dispute, call `settlement.dispute()` from the `PAYMENT_PENDING` state:

```typescript
// Raise a dispute with a reason and optional evidence
const dispute = await client.settlement.dispute(
  escrow.id,
  'Fiat payment not received after 2 hours',
);
console.log('Dispute ID:', dispute.id);
console.log('Status:', dispute.status); // 'OPENED'
```

## Client-Held Keys

The `MULTISIG`, `LIGHTNING_HODL`, and `SAFE_GUARD_EVM` providers require you to generate a keypair and submit your public key to the escrow. The private key never leaves your device. When it is time to release or refund, you sign the transaction locally and submit only the signed bytes.

```typescript
import { generateEscrowKeypair, signEscrowPsbt } from '@satsails/p2p-trading-sdk';

// Generate a keypair — store the private key securely!
const { publicKey, privateKey } = generateEscrowKeypair();

// Submit your public key to the escrow
await client.settlement.submitKey(escrow.id, publicKey);
```

When the seller is ready to release funds, they initiate the release and sign the resulting unsigned PSBT:

```typescript
// Initiate release — this creates an unsigned transaction, it does not move funds yet
const pendingTx = await client.settlement.initiateRelease(escrow.id, buyerPayoutAddress);

// Sign the PSBT with your local private key
const signedPsbt = signEscrowPsbt(pendingTx.unsignedPsbtBase64, privateKey);

// Submit the signature — once all required parties have signed, funds are released
await client.settlement.submitTransactionSignature(escrow.id, signedPsbt);
```

You can retrieve the pending transaction at any time before signing:

```typescript
const pendingTx = await client.settlement.getPendingTransaction(escrow.id);
```

For `LIGHTNING_HODL` escrows, use `signEscrowArkTx()` instead of `signEscrowPsbt()`. For `SAFE_GUARD_EVM`, use `signEscrowSafeUserOp()`.

<Warning>
  For `MULTISIG` and `LIGHTNING_HODL` escrows, **you must store your private key yourself**. Sails never receives it. If you lose your private key before an escrow is released, the funds cannot be released without opening a dispute and engaging an arbiter. Treat your escrow keypair with the same care as your wallet seed phrase.
</Warning>
