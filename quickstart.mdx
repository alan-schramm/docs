title: "Sails Protocol Quickstart: P2P Trade in 15 Minutes"
sidebarTitle: "Quickstart"
description: "Run a local Sails node, install the Sails P2P Trading SDK, and complete a full P2P trade — identity, offer, trade, chat, escrow, release, and rating — in under 15 minutes."
---

This guide runs a complete trade with the Sails P2P Trading SDK against a local node: two participants register, one publishes an offer, the other opens a trade, they chat, and the escrow is locked, paid, and released. It uses only the SDK's public API.

<Note>
  The local Docker setup runs with **mock escrow**: every escrow uses the `MOCK` provider, so no real funds move. That's what makes the whole flow scriptable. Real providers (`MULTISIG`, `LIGHTNING_HODL`, …) need on-chain funding and client-side signing — see [Escrow Lifecycle](/guides/escrow-lifecycle).
</Note>

<Steps>
  <Step title="Start a local node">
    From the Sails Protocol repository:

    ```bash
    docker compose up -d --build
    ```

    This starts PostgreSQL, Redis, and the node at `http://localhost:3000`. Check it's ready:

    ```bash
    curl http://localhost:3000/health/ready
    ```
  </Step>
  <Step title="Install the SDK">
    <CodeGroup>

    ```bash npm
    npm install @satsails/p2p-trading-sdk
    ```

    ```bash yarn
    yarn add @satsails/p2p-trading-sdk
    ```

    ```bash pnpm
    pnpm add @satsails/p2p-trading-sdk
    ```

    </CodeGroup>
  </Step>
  <Step title="Create two participants">
    Each side of a trade is its own participant with its own client and session. `identity.create()` generates an Ed25519 keypair, proves possession of it, and registers it; `authenticate()` signs a challenge and stores the session on the client.

    ```typescript
    import { SailsClient } from '@satsails/p2p-trading-sdk';
    
    const baseUrl = 'http://localhost:3000';
    const seller = new SailsClient({ baseUrl });
    const buyer = new SailsClient({ baseUrl });
    
    const { participant: sellerId, keypair: sellerKeys } = await seller.identity.create(undefined, 'Seller');
    await seller.identity.authenticate(sellerKeys);
    
    const { participant: buyerId, keypair: buyerKeys } = await buyer.identity.create(undefined, 'Buyer');
    await buyer.identity.authenticate(buyerKeys);
    ```

    <Warning>
      The keypair is the identity's only credential — there's no password reset. Store `secretKey` securely in a real app, or use `createWithWallet()` so the key never leaves the wallet.
    </Warning>
  </Step>
  <Step title="Register the buyer's payout address">
    Releases always pay out to the beneficiary's registered address for the asset — never to an address passed at release time. Register it before trading:

    ```typescript
    await buyer.settlement.setPayoutAddress({ asset: 'USDT_ERC20', address: '0xYourBuyerAddress' });
    ```
  </Step>
  <Step title="Publish an offer">
    ```typescript
    const offer = await seller.liquidity.publish({
      asset: 'USDT_ERC20',
      side: 'SELL',
      priceUsd: '1.00',
      minAmount: '1',
      maxAmount: '100',
      paymentMethod: 'PIX',
      paymentDetails: 'seller-pix-key',
    });
    ```

    Amounts and prices are decimal strings. `paymentDetails` is never returned by the public offer endpoints.
  </Step>
  <Step title="Discover it and open a trade">
    ```typescript
    const { offers } = await buyer.liquidity.discover({ asset: 'USDT_ERC20', side: 'SELL', limit: 20 });
    const chosen = offers.find((o) => o.id === offer.id)!;
    
    const trade = await buyer.openp2p.trade(chosen.id, '10');
    ```
  </Step>
  <Step title="Chat">
    `chat()` fetches a WebSocket ticket, joins the trade, and reconnects automatically:

    ```typescript
    const sellerChat = seller.openp2p.chat(trade.id);
    const buyerChat = buyer.openp2p.chat(trade.id);
    
    sellerChat.onMessage((msg) => console.log('Seller got:', msg.content));
    buyerChat.send({ content: 'Sending payment now via PIX.' });
    ```

    Messages are relayed and stored by the node. Close channels when you're done with `close()`.
  </Step>
  <Step title="Lock, pay, release">
    ```typescript
    // Seller creates and locks the escrow.
    const escrow = await seller.settlement.create({ tradeId: trade.id, lockedAmount: '10', asset: 'USDT_ERC20' });
    await seller.settlement.lock(escrow.id);
    
    // Buyer pays off-chain (PIX), then records it.
    await buyer.settlement.markPaymentSent(escrow.id);
    
    // Seller confirms receipt and releases to the buyer's registered address.
    const released = await seller.settlement.release(escrow.id);
    console.log(released.status); // COMPLETED
    ```
  </Step>
  <Step title="Rate the trade">
    ```typescript
    await buyer.reputation.rate({ tradeId: trade.id, ratedId: sellerId.id, score: 5 });
    const score = await seller.reputation.get(sellerId.id);
    console.log(score.totalTrades);
    ```

    Ratings are informational; the trust score comes from settlement outcomes.
  </Step>
</Steps>

<Tip>
  Production nodes enforce capability grants. After authenticating against one, call `client.capabilities.ensureCanonicalGrants(participantId)` once — it's idempotent. See [Capabilities](/api/capabilities).
</Tip>
