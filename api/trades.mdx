---

Once you've found an offer through [Liquidity](/api/liquidity), the OpenP2P module opens a trade between you and the offer's owner, carries the negotiation channel, and tracks the trade until settlement. Every endpoint here requires a session, and your participant ID always comes from that session — never from the request body.

| Method | Path | Description |
| --- | --- | --- |
| POST | `/v1/openp2p/trades` | Open a trade against an offer |
| GET | `/v1/openp2p/trades` | List your trades (paginated) |
| GET | `/v1/openp2p/trades/:id` | Trade detail (buyer or seller only) |
| GET | `/v1/openp2p/trades/by-intent/:intentId` | The trade an intent produced |
| PATCH | `/v1/openp2p/trades/:id/status` | Set status to `ACTIVE` or `CANCELLED` |
| POST | `/v1/openp2p/trades/:id/reconcile` | Messages and status you missed while offline |
| GET | `/v1/openp2p/chat/:tradeId/messages` | Message history (paginated) |
| WS | `/v1/openp2p/chat?ticket=…` | Real-time trade channel — see [WebSocket](/api/websocket) |

## Open a trade

**`POST /v1/openp2p/trades`**

<ParamField body="offerId" type="string" required>
  The offer to trade against, from `GET /v1/liquidity/offers` or `POST /v1/liquidity/match`.
</ParamField>

<ParamField body="amount" type="string" required>
  Amount of the asset, as a decimal string, within the offer's `minAmount`–`maxAmount`.
</ParamField>

<ParamField body="idempotencyKey" type="string">
  Optional (up to 200 characters). Retrying with the same key returns the same trade instead of opening a second one.
</ParamField>

Returns `201` with the new trade. You become the counterparty to the offer's owner.

<CodeGroup>
```bash Request
curl -X POST http://localhost:3000/v1/openp2p/trades \
  -H "Authorization: Bearer <sessionToken>" \
  -H "Content-Type: application/json" \
  -d '{ "offerId": "…", "amount": "0.01", "idempotencyKey": "order-8841" }'
```

```json Response (201)
{
  "success": true,
  "data": {
    "id": "…",
    "offerId": "…",
    "buyerId": "…",
    "sellerId": "…",
    "asset": "BTC",
    "amount": "0.01",
    "priceUsd": "65000",
    "totalUsd": "650",
    "status": "ACTIVE",
    "createdAt": "2026-09-21T10:05:00.000Z"
  }
}
```
</CodeGroup>

## List your trades

**`GET /v1/openp2p/trades`**

Returns the trades where you are buyer or seller.

<ParamField query="limit" type="integer">
  1–100.
</ParamField>

<ParamField query="offset" type="integer">
  Number of items to skip.
</ParamField>

---

## Get a trade

**`GET /v1/openp2p/trades/:id`**

Returns the trade with its escrow, messages, and originating offer. Returns `403 FORBIDDEN` if you're not the buyer or seller.

---

## Resolve a trade from an intent

**`GET /v1/openp2p/trades/by-intent/:intentId`**

Returns the trade created from an intent (see [Intents](/concepts/intents)). Buyer or seller only.

---

## Update trade status

**`PATCH /v1/openp2p/trades/:id/status`**

<ParamField body="status" type="string" required>
  `ACTIVE` or `CANCELLED`.
</ParamField>

Only a party to the trade can change its status.

<Note>
  A trade cancelled by agreement is always a **neutral** reputation outcome — it never lowers either party's score. If your counterparty stops cooperating after funds are locked, open a dispute through [Settlement](/api/settlement) instead.
</Note>

---

## Catch up after a disconnection

**`POST /v1/openp2p/trades/:id/reconcile`**

<ParamField body="sinceMessageCreatedAt" type="string">
  ISO timestamp of the last message you have. Omit it to get messages from the beginning.
</ParamField>

<ResponseField name="currentTradeStatus" type="string">
  The trade's status now.
</ResponseField>

<ResponseField name="currentEscrowStatus" type="string | null">
  The escrow's status now, or `null` if no escrow exists yet.
</ResponseField>

<ResponseField name="missedMessages" type="array">
  Up to 100 messages created after `sinceMessageCreatedAt`, oldest first.
</ResponseField>

---

## Message history

**`GET /v1/openp2p/chat/:tradeId/messages`**

<ParamField query="limit" type="integer">
  1–100.
</ParamField>

<ParamField query="offset" type="integer">
  Number of messages to skip.
</ParamField>

Only a party to the trade can read its messages.

<Note>
  Chat messages are relayed and stored by the node. They aren't end-to-end encrypted between the two parties, so don't share secrets you wouldn't store with the node operator.
</Note>

## Errors

| `error` | HTTP | When |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | Missing field, or `amount` outside the offer's limits |
| `AUTH_ERROR` | 401 | Missing or expired session |
| `FORBIDDEN` | 403 | You're not a party to this trade |
| `NOT_FOUND` | 404 | The trade, offer, or intent doesn't exist |
| `RATE_LIMIT_EXCEEDED` | 429 | Too many requests |
