Sails Protocol authenticates participants with Ed25519 signatures. You register a public key (proving you hold its private key), sign a server-issued challenge, and receive a session token — no passwords or API keys. Your private key never leaves your device.

## Step-by-step authentication

<Steps>
  <Step title="Request a registration challenge">
    Registration requires proof that you hold the private key for the public key you register. Ask for a one-time registration challenge first:

    ```bash
    POST /v1/identity/register-challenge
    Content-Type: application/json
    
    { "publicKey": "<64-char hex Ed25519 public key>" }
    ```

    ```json
    { "success": true, "data": { "challenge": "9f2c…e1", "expiresIn": 120 } }
    ```
  </Step>
  <Step title="Register the participant">
    Sign this exact UTF-8 message with your Ed25519 private key:

    ```text
    sails-registration-proof-of-possession:v1:<challenge>:<displayName or empty>
    ```

    Then register, sending the hex-encoded signature:

    ```bash
    POST /v1/identity/participants
    Content-Type: application/json
    
    {
      "publicKey": "<64-char hex Ed25519 public key>",
      "signature": "<hex Ed25519 signature of the message above>",
      "displayName": "My App"
    }
    ```

    The node responds with `201` and your participant record. Save the `id`. The display name is part of the signed message, so it can't be altered in transit. Registering a key that's already registered returns `VALIDATION_ERROR` (400); a missing, invalid, expired, or already-used proof returns `AUTH_ERROR` (401).
  </Step>
  <Step title="Request a login challenge">
    ```bash
    POST /v1/identity/challenge
    Content-Type: application/json
    
    { "publicKey": "<64-char hex Ed25519 public key>" }
    ```

    ```json
    { "success": true, "data": { "challenge": "4ab7…0c", "expiresIn": 120 } }
    ```

    The challenge is 32 random bytes encoded as a 64-character hex string. It expires after `expiresIn` seconds (120 by default) and can be used once.
  </Step>
  <Step title="Sign the challenge and authenticate">
    Sign the **UTF-8 bytes of the challenge string itself** — not the decoded hex bytes — and submit the hex-encoded signature:

    ```bash
    POST /v1/identity/authenticate
    Content-Type: application/json
    
    {
      "publicKey": "<64-char hex Ed25519 public key>",
      "signature": "<hex Ed25519 signature of the challenge string>"
    }
    ```

    ```json
    {
      "success": true,
      "data": {
        "participantId": "5b1c2d3e-…",
        "sessionToken": "<64-char hex token>"
      }
    }
    ```
  </Step>
  <Step title="Send the token on every request">
    ```text
    Authorization: Bearer <sessionToken>
    ```

    The session token is opaque and lasts one hour by default. When it expires, requests return `AUTH_ERROR` (401) — request a new challenge and authenticate again.
  </Step>
</Steps>

## Using the SDK

The Sails P2P Trading SDK (`@satsails/p2p-trading-sdk`) runs the whole flow for you, including the proof of possession:

```typescript
import { SailsClient } from '@satsails/p2p-trading-sdk';

const client = new SailsClient({ baseUrl: 'http://localhost:3000' });

// Generates a keypair (or uses yours), requests a registration challenge,
// signs the proof of possession, and registers the participant.
const { participant, keypair } = await client.identity.create(undefined, 'My App');

// Challenge → sign → authenticate. The session token is stored on the client
// and attached to every later request.
await client.identity.authenticate(keypair);

const me = await client.identity.me();
```

If a wallet holds the key, use the wallet-backed methods — the SDK only asks the wallet to sign messages and never sees a secret key:

```typescript
const wallet = { signMessage: async (message: Uint8Array) => myWallet.signEd25519(message) };

const participant = await client.identity.createWithWallet(publicKeyHex, wallet, 'My App');
await client.identity.authenticateWithWallet(publicKeyHex, wallet);
```

<Warning>
  `identity.createWithPublicKey()` is deprecated. The node now requires proof of possession at registration, which that method can't produce — use `createWithWallet()` instead.
</Warning>

To persist or restore a session:

```typescript
const token = client.getSessionToken();
client.setSessionToken(token); // e.g. on a new client instance
```

## WebSocket tickets

Browsers can't set an `Authorization` header on a WebSocket upgrade, so WebSocket channels authenticate with a ticket instead of the session token:

```bash
POST /v1/identity/ws-ticket
Authorization: Bearer <sessionToken>
```

```json
{ "success": true, "data": { "ticket": "<64-char hex>", "expiresIn": 30 } }
```

Open the socket with `?ticket=<ticket>` within `expiresIn` seconds. Each ticket works once. The SDK's `openp2p.chat()` fetches tickets automatically, including on reconnect. See [WebSocket](/api/websocket).

## Error codes

| Code | HTTP | When it occurs |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | `publicKey` isn't 64 hex characters, a field is missing, or the key is already registered |
| `AUTH_ERROR` | 401 | Signature didn't verify, the challenge expired or was already used, no participant exists for this key, or the session token is missing or expired |
| `NOT_FOUND` | 404 | The participant doesn't exist |
| `RATE_LIMIT_EXCEEDED` | 429 | Too many registration or authentication attempts |

<Warning>
  Never send your private key anywhere. The node only ever sees your public key and signatures over one-time challenges.
</Warning>
