---
title: "OpenReputation API: Trust Scores, Ratings, and Vouches"
sidebarTitle: "Reputation"
description: "REST endpoints for reading participant trust scores, browsing the leaderboard, rating trade counterparties, and vouching for new participants."
---

OpenReputation exposes each participant's trust score and trade history counters, a leaderboard, post-trade ratings, and peer vouching. The score is driven by settlement outcomes recorded by the protocol — ratings submitted through `POST /v1/reputation/rate` are informational and never change it.

| Method | Path | Auth | Description |
| --- | --- | --- | --- |
| GET | `/v1/reputation/:participantId` | — | Score for a participant |
| GET | `/v1/reputation/peer/:peerId` | — | Same score, looked up by portable P2P identity |
| GET | `/v1/reputation/leaderboard` | — | Top participants by score (paginated) |
| POST | `/v1/reputation/rate` | Session | Rate a counterparty after a trade (informational) |
| POST | `/v1/reputation/vouch` | Session | Vouch for another participant |

---

## Get a participant's score

**`GET /v1/reputation/:participantId`**

```json
{
  "success": true,
  "data": {
    "participantId": "5b1c2d3e-…",
    "total": 42,
    "tradeScore": 0,
    "volumeScore": 0,
    "settlementScore": 0,
    "disputeRate": 0.02,
    "totalTrades": 48,
    "cumulativeFeesObserved": "0.00012"
  }
}
```

<ResponseField name="total" type="number">
  The participant's reputation score, updated from settlement outcomes.
</ResponseField>

<ResponseField name="tradeScore / volumeScore / settlementScore" type="number">
  Reserved score components. Always `0` today — they aren't tracked separately yet. Use `total`.
</ResponseField>

<ResponseField name="disputeRate" type="number">
  Disputes divided by completed trades (`0` with no trades).
</ResponseField>

<ResponseField name="totalTrades" type="number">
  Completed trades.
</ResponseField>

<ResponseField name="cumulativeFeesObserved" type="string">
  Protocol fees observed across this participant's trades, as a decimal string.
</ResponseField>

The score contains no profile data — call `GET /v1/identity/participants/:id` for the display name or public key.

---

## Get a score by peer ID

**`GET /v1/reputation/peer/:peerId`**

Resolves a portable Pears (HyperDHT) identity to its participant and returns the same shape as above. Useful when you know a counterparty's peer key but not their participant ID.

## Leaderboard

**`GET /v1/reputation/leaderboard`**

<ParamField query="limit" type="integer">
  1–100.
</ParamField>

<ParamField query="offset" type="integer">
  Number of entries to skip.
</ParamField>

```json
{
  "success": true,
  "data": {
    "items": [
      { "id": "5b1c…", "displayName": "alice_trader", "reputationScore": 97, "totalTrades": 120 }
    ],
    "total": 500,
    "hasMore": true,
    "nextOffset": 10
  }
}
```

`nextOffset` is `null` on the last page.

## Rate a counterparty

**`POST /v1/reputation/rate`**

<ParamField body="tradeId" type="string" required>
  The trade you're rating.
</ParamField>

<ParamField body="ratedId" type="string" required>
  The counterparty's participant ID.
</ParamField>

<ParamField body="score" type="integer" required>
  1 (poor) to 5 (excellent).
</ParamField>

<ParamField body="comment" type="string">
  Optional feedback.
</ParamField>

<Note>
  Ratings are informational. They don't change the score returned by `GET /v1/reputation/:participantId`, so a counterparty can't lower your score with a punitive rating. A trade cancelled by agreement is always a neutral outcome.
</Note>

## Vouch for a participant

**`POST /v1/reputation/vouch`**

<ParamField body="voucheeId" type="string" required>
  The participant you're vouching for.
</ParamField>

A vouch is a protocol-level attestation backed by your own standing — not an identity check. When the vouchee registers their first payment account, it starts pre-attested by your vouch. If that account is later abused, your own reputation is penalized.

<Warning>
  To vouch you need at least 3 completed trades and a positive reputation. You can vouch for a given participant only once — a repeat vouch or an ineligible caller returns `400`.
</Warning>
