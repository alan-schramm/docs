---
title: "Sails Peers: Start HyperDHT Nodes and Discover Peers"
sidebarTitle: "Peers"
description: "REST endpoints for starting and stopping your HyperDHT node, joining discovery topics and per-trade channels, and broadcasting offers to connected peers."
---

The Peers API manages your participant's presence on HyperDHT — the Pears (Holepunch) P2P transport that lets participants discover each other and exchange data directly, with NAT traversal. The node keeps one P2P node per participant in a server-side registry, so many participants can share the same process.

<Note>
  The Peers API is optional. HTTP offer discovery through [Liquidity](/api/liquidity) works without it. All endpoints require a session.
</Note>

| Method | Path | Description |
| --- | --- | --- |
| POST | `/v1/peers/start` | Start your HyperDHT node |
| POST | `/v1/peers/stop` | Stop your node |
| GET | `/v1/peers/status` | Your node's connection status |
| POST | `/v1/peers/join-topic` | Announce on a discovery topic |
| POST | `/v1/peers/join-trade` | Join a trade's private topic |
| POST | `/v1/peers/broadcast-offer` | Send an offer to connected peers |

---

## Start your node

**`POST /v1/peers/start`**

No body. The node generates an ephemeral Ed25519 P2P identity for your session — you never send a key.

```json Response (data)
{ "peerId": "a1b2c3d4…", "transport": "…" }
```

`peerId` is your node's public key — a portable P2P identity you can share with counterparties.

## Stop your node

**`POST /v1/peers/stop`** — disconnects from all topics and channels. Trades continue through the HTTP API.

## Status

**`GET /v1/peers/status`** — your node's connection status, peer count, and active topics.

## Join a discovery topic

**`POST /v1/peers/join-topic`**

<ParamField body="topic" type="string" required>
  `marketplace`, `btc`, `lnBtc`, `liquidBtc`, `usdtErc20`, or `usdtLiquid`.
</ParamField>

## Join a trade's topic

**`POST /v1/peers/join-trade`**

<ParamField body="tradeId" type="string" required>
  A trade you're a party to.
</ParamField>

Joins a topic scoped to that trade, so trade-specific data only reaches its counterparty. Returns `409` if you haven't started a node.

## Broadcast an offer

**`POST /v1/peers/broadcast-offer`**

<ParamField body="offerId" type="string" required>
  The offer to broadcast.
</ParamField>

<ParamField body="asset" type="string" required>
  The offer's asset.
</ParamField>

<ParamField body="side" type="string" required>
  `BUY` or `SELL`.
</ParamField>

<ParamField body="priceUsd" type="string" required>
  The offer's price, as a decimal string.
</ParamField>

```json Response (data)
{ "deliveredTo": 12 }
```

`deliveredTo` is the number of connected peers that received it. Returns `409` if you haven't started a node.

<Warning>
  Broadcasting doesn't publish the offer to the HTTP offer book. Publish it with `POST /v1/liquidity/offers` first if you want it discoverable through both.
</Warning>
