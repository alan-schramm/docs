`SailsClient` is the single entry point to the Sails P2P Trading SDK (`@satsails/p2p-trading-sdk`). Construct one instance per application.

<Note>
  This page follows the SDK's pre-v1 compatibility contract (`0.2.0`): documented methods don't change incompatibly before v1. Methods marked **additive** are real and callable but may still gain fields; `negotiate()` is **experimental**.
</Note>

## Constructor

```typescript
import { SailsClient } from '@satsails/p2p-trading-sdk';

const client = new SailsClient({
  baseUrl: process.env.SAILS_BASE_URL ?? 'http://localhost:3000',
  wallet: myWalletAdapter,        // optional
  onSessionExpired: (err) => {},  // optional — called when the session expires
});
```

| Option | Type | Description |
| --- | --- | --- |
| `baseUrl` | `string` (required) | URL of your Sails node. HTTP and WebSocket connections resolve against it. |
| `wallet` | `WalletAdapter` | Plugs your wallet's balance, address, transaction, and signing logic into the client. See [Wallet Adapter](/guides/wallet-adapter). |
| `fetchImpl` | `typeof fetch` | Custom `fetch` (proxies, custom runtimes). |
| `webSocketImpl` | `typeof WebSocket` | WebSocket constructor for runtimes without a global `WebSocket`. |
| `timeoutMs` | `number` | Per-request timeout. |
| `maxRetries` / `retryDelayMs` | `number` | Retry policy for `GET` requests (see [Errors and retries](#errors-and-retries)). |
| `onSessionExpired` | `(err: SailsAuthError) => void` | Called when a request fails because the session expired. You can also set it later with `client.setOnSessionExpired()`. |

## Modules

Several modules have a protocol name and a friendly alias. Both point to the same object.

| Protocol name | Alias | What it does |
| --- | --- | --- |
| `identity` | `auth` | Registration with proof of possession, challenge-response auth, session |
| `liquidity` | `offers` | Publish, discover, and manage offers; order book |
| `openp2p` | `trades` | Trades, message history, real-time chat |
| `settlement` | `escrow` | Escrow lifecycle, signing rounds, disputes, payout addresses |
| `reputation` | `trustScore` | Trust score, leaderboard, ratings, vouches |
| `arbitration` | — | Permissionless arbiter registration (market arbitration) |
| `paymentAccounts` | — | Payment-account trust ramp |
| `proof` | — | Claims, proofs, verification, evidence, bundles |
| `agents` | — | On-device AI: intent drafts and risk assessment (additive) |
| `peers` | — | HyperDHT P2P node |
| `capabilities` | — | Capability grants |

Methods marked _session_ need an authenticated client (see `identity.authenticate()`).

## `identity` / `auth`

```typescript
// Generate (or pass) a keypair, prove possession, and register.
const { participant, keypair } = await client.identity.create(undefined, 'Alice');
await client.identity.authenticate(keypair); // stores the session on the client

// Wallet-held key: the SDK only asks the wallet to sign.
await client.identity.createWithWallet(publicKeyHex, wallet, 'Alice');
await client.identity.authenticateWithWallet(publicKeyHex, wallet);

const me = await client.identity.me();             // session
const someone = await client.identity.get(otherId); // public view
```

| Method | Returns | Notes |
| --- | --- | --- |
| `create(keypair?, displayName?)` | `{ participant, keypair }` | Generates a keypair if omitted. Store `keypair.secretKey` safely — it can't be recovered. |
| `createWithWallet(publicKeyHex, wallet, displayName?)` | `Participant` | Additive. Proof of possession signed by `wallet.signMessage()`. |
| `registerChallenge(publicKeyHex)` | `{ challenge, expiresIn }` | Additive. Low-level registration challenge. |
| `createWithPublicKey(publicKeyHex, displayName?)` | `Participant` | **Deprecated** — can't produce the proof of possession the node requires. Use `createWithWallet()`. |
| `get(participantId)` | `PublicParticipant` | Public identity fields only. |
| `me()` | `Participant` | Session. |
| `challenge(publicKeyHex)` | `{ challenge, expiresIn }` | Low-level login challenge. |
| `authenticate(keypair)` | `{ participantId, sessionToken }` | Stores the session on the client. |
| `authenticateWithWallet(publicKeyHex, wallet)` | `{ participantId, sessionToken }` | Stores the session; never touches a secret key. |

`generateKeypair()` is also exported as a standalone helper.

## `liquidity` / `offers`

```typescript
const offer = await client.liquidity.publish({ // session
  asset: 'BTC', side: 'SELL', priceUsd: '65000',
  minAmount: '0.001', maxAmount: '0.1', paymentMethod: 'PIX',
});

const { offers, total, hasMore } = await client.liquidity.discover({ asset: 'BTC', side: 'SELL', limit: 20 });
const detail = await client.liquidity.getOffer(offer.id);
const { bids, asks, spread } = await client.liquidity.book('BTC');
const best = await client.liquidity.match({ asset: 'BTC', side: 'BUY', amount: '0.01' });
await client.liquidity.updateStatus(offer.id, 'PAUSED'); // session
const mine = await client.liquidity.getMyOffers();        // session
```

| Method | Returns |
| --- | --- |
| `discover({ asset, side, limit?, offset?, paymentMethod?, priceMin?, priceMax? })` | `{ offers, sources, total, hasMore }` — `limit` defaults to 10, max 50 |
| `getOffer(offerId)` | Offer with the owner's public profile |
| `publish(input)` | `Offer` (session) |
| `book(asset)` | `OrderBook` |
| `updateStatus(offerId, status)` | `Offer` (session) — `ACTIVE`, `PAUSED`, `COMPLETED`, `CANCELLED` |
| `match({ asset, side, amount })` | Best offer summary, or `null` |
| `getMyOffers()` | Your `Offer` rows, including non-active ones (session) |

<Note>
  All amounts and prices are decimal strings (`"0.001"`), never `number`s — passing a number throws before any request is sent.
</Note>

## `openp2p` / `trades`

```typescript
const trade = await client.openp2p.trade(offerId, '0.001');    // session
const same = await client.openp2p.getTrade(trade.id);           // session, party only
const fromIntent = await client.openp2p.getTradeByIntent(intentId);
await client.openp2p.updateTradeStatus(trade.id, 'CANCELLED');  // session
const history = await client.openp2p.getMessages(trade.id, { limit: 50 });

const channel = client.openp2p.chat(trade.id); // tickets, join, reconnect handled for you
channel.onMessage((msg) => console.log(msg.content));
channel.send({ content: 'Payment sent.' });
```

| Method | Returns |
| --- | --- |
| `trade(offerId, amount, idempotencyKey?)` | `Trade` (session) |
| `getTrades({ limit?, offset? }?)` | Your trades, paginated (session) |
| `getTrade(tradeId)` / `getTradeByIntent(intentId)` | `Trade` (session, party only) |
| `updateTradeStatus(tradeId, status)` | `Trade` (session) — `ACTIVE` or `CANCELLED` |
| `getMessages(tradeId, { limit?, offset? }?)` | Paginated messages (session) |
| `chat(tradeId, options?)` | `WebSocketChannel` — `onMessage`, `onEvent`, `send`, `leave`, `close`, `onConnectionStateChange` (`'open'`, `'reconnecting'`, `'closed'`) |
| `reconcileTrade(tradeId, sinceMessageCreatedAt)` | Catch-up after a disconnection: `{ tradeId, currentTradeStatus, currentEscrowStatus, missedMessages }` at runtime (session) |

See [WebSocket](/api/websocket) for the frames.

## `settlement` / `escrow`

```typescript
import { generateEscrowKeypair, signEscrowPsbt } from '@satsails/p2p-trading-sdk';

await client.settlement.setPayoutAddress({ asset: 'BTC', address: myBtcAddress }); // before trading

const escrow = await client.settlement.create({ tradeId: trade.id, lockedAmount: '0.001', asset: 'BTC' });

// Client-held keys (MULTISIG / LIGHTNING_HODL / SAFE_GUARD_EVM)
const escrowKey = generateEscrowKeypair();
await client.settlement.submitKey(escrow.id, escrowKey.publicKeyHex);

await client.settlement.lock(escrow.id);            // seller
await client.settlement.markPaymentSent(escrow.id); // buyer

// Release through a signing round
const pending = await client.settlement.initiateRelease(escrow.id);
const signed = signEscrowPsbt(pending.unsignedPsbtBase64, escrowKey.privateKey);
const { complete } = await client.settlement.submitTransactionSignature(escrow.id, signed);
```

| Method | Returns / notes |
| --- | --- |
| `create(input)` | `Escrow` (session). `type` optional — the node picks the provider for the asset. |
| `get(escrowId)` | `Escrow` (session, party or assigned arbiter) |
| `submitKey(escrowId, pubkeyHex)` | `{ escrow, buyerKeySubmitted, sellerKeySubmitted }` |
| `lock(escrowId)` / `markPaymentSent(escrowId)` | `Escrow` (seller / buyer) |
| `release(escrowId, toAddress?)` / `refund(escrowId)` | `Escrow` — direct-call providers only. `toAddress` is ignored: payouts go to the registered address. |
| `initiateRelease(escrowId, toAddress?)` / `initiateRefund(escrowId)` | `EscrowPendingTransaction` — `kind`, `requiredSigners`, `unsignedPsbtBase64`. `toAddress` is ignored. |
| `submitTransactionSignature(escrowId, signedPsbtBase64)` | `{ complete }` |
| `getPendingTransaction(escrowId)` | `EscrowPendingTransaction` (session, party or arbiter); throws `SailsNotFoundError` when none |
| `approveRelease(escrowId)` / `getReleaseApprovals(escrowId)` | Two-person approval (session) |
| `dispute(escrowId, reason, evidence?)` | `Dispute` (session) |
| `initiateExpiryRecovery(escrowId)` | `Dispute` — seller recovers an `EXPIRED` escrow |
| `listDisputes(pagination?)` | Disputes assigned to you as arbiter (session) |
| `getDispute(disputeId)` | `Dispute` (session, party or arbiter) |
| `getSemanticRecord(disputeId, appealRound)` | Durable ruling record (session, party) |
| `submitDisputeEvidence(disputeId, descriptor)` / `contestAutoResolution(disputeId)` | `Dispute` (session, party) |
| `resolveDisputeWithWallet(disputeId, ruling, wallet, releaseToAddress?, refundToAddress?, splitBuyerBps?)` | `Dispute` — builds and wallet-signs the ruling (assigned arbiter) |
| `resolveDispute(disputeId, ruling, releaseToAddress?, refundToAddress?, splitBuyerBps?, authoritySignature?, authorityIssuedAt?)` | `Dispute` — low-level; the two signature fields are required in practice |
| `appealDispute(disputeId)` | `{ dispute, appealFeeRequired }` (market arbitration) |
| `setPayoutAddress({ asset, address })` / `getPayoutAddress(participantId, asset)` | Your payout address (session; self only) |

Client-held-key signing helpers are top-level exports: `generateEscrowKeypair()`, `signEscrowPsbt()` (`MULTISIG`), `signEscrowArkTx()` (`LIGHTNING_HODL`), `signEscrowSafeUserOp()` and `parseSafeGuardBundle()` (`SAFE_GUARD_EVM`). `canonicalizeAuthorityDecision()` and `hashAuthorityDecision()` are exported for arbiters who build rulings manually.

## Intent facade

These methods sit directly on `client`:

```typescript
const intent = await client.createIntent('TradeIntent', {
  asset: 'BTC', side: 'BUY', maxValue: '500', currency: 'USD', fiatMethod: 'PIX',
  maxPriceUsd: '66000', minReputationRating: 4,
});

const proposal = await client.proposeTrade(intent.id, '0.001');
if (proposal) await client.openp2p.trade(proposal.offerId, '0.001');
```

| Method | Returns / notes |
| --- | --- |
| `createIntent('TradeIntent', payload, agentId?)` | `Intent` — requires the `trade-coordination` capability where enforced |
| `cancelIntent(intentId)` | — |
| `proposeTrade(intentId, amount)` | `TradeProposal \| null` — a matching offer within your limits; never opens a trade itself |
| `proposeTradeOutcome(intentId, amount)` | Additive. `{ proposal, counterProposal }` — `counterProposal` suggests your own price bound when only price missed |
| `submitProof(intentId, proof)` | `Proof` |
| `releaseAsset(intentId, toAddress?)` | `Escrow` |
| `dispute(intentId, reason)` | `Dispute` |
| `negotiate(intentId, event)` | **Experimental** — throws `SailsNotImplementedError`. Use `openp2p.chat()`. |

## Wallet helpers

When you pass a `wallet`, the client exposes `getBalance(asset)`, `getWalletAddresses()`, `sendTransaction(asset, tx)`, `signMessage(message)`, and `getCapabilities()`, which delegate to it.

## Errors and retries

The SDK throws typed errors, all extending `SailsError`: `SailsValidationError`, `SailsAuthError`, `SailsForbiddenError`, `SailsNotFoundError`, `SailsEscrowError`, `SailsRateLimitError`, `SailsInternalError`, `SailsTransportError`, `SailsConfigError`, and `SailsNotImplementedError`.

```typescript
import { SailsAuthError, SailsRateLimitError } from '@satsails/p2p-trading-sdk';

try {
  await client.openp2p.trade(offerId, '0.001');
} catch (err) {
  if (err instanceof SailsAuthError) {
    // session expired — authenticate again
  } else if (err instanceof SailsRateLimitError) {
    // back off before retrying
  }
}
```

`GET` requests retry automatically on `429`, `502`, `503`, and `504`, honoring the server's `Retry-After` header when present and otherwise backing off exponentially. `POST`, `PATCH`, and `DELETE` are never retried automatically — decide yourself whether a retry is safe (and use `idempotencyKey` where the endpoint supports it).
