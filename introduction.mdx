Sails Protocol is open infrastructure for building interoperable **P2P financial marketplaces**. It provides the identity, liquidity discovery, trade coordination, escrow and settlement, dispute, and reputation layers that wallets, fintechs, and OTC desks need to let their users trade directly with each other — standardized once, so nobody rebuilds them from scratch.

The **Sails P2P Trading SDK** (`@satsails/p2p-trading-sdk`) is the primary way to integrate. You bring the product and the users; a Sails node brings the coordination.

## The stack

Sails coordinates proven components rather than reinventing them:

- **WDK (Tether's Wallet Development Kit)** — wallet and settlement building blocks. The `WDK_USDT_EVM` provider uses it for real on-chain USDT execution (as a server-custodial reference implementation).
- **Pears (Holepunch)** — HyperDHT peer discovery and direct, NAT-traversed connections between participants' nodes, alongside the node's regular HTTP and WebSocket APIs.
- **QVAC (Tether)** — local AI (llama.cpp) running on the Sails node, with no cloud AI service. It drafts intents and offers, assesses risk, flags social-engineering patterns, and can propose advisory dispute rulings.

See [Architecture](/architecture) for how they fit together.

## Modules

| Module | What it does |
| --- | --- |
| **OpenIdentity** | Ed25519 identities with proof of possession and challenge-response sessions |
| **OpenLiquidity** | Offer publication, discovery, order book, and matching |
| **OpenP2P** | Trades, trade chat, and trade status |
| **OpenSettlement** | Pluggable escrow providers, signing rounds, disputes, arbitration, payout addresses |
| **OpenReputation** | Outcome-based trust scores, ratings, and vouches |
| **OpenProof** | The `Claim → Proof → Verification` chain for payment and dispute evidence |
| **OpenAgents** | Local-AI assistance and capability grants |
| **OpenFinance** | Future: lending, swaps, and yield intents reusing the same layers |

## Principles

- **No central custodian.** Client-held-key providers (`MULTISIG`, `LIGHTNING_HODL`, `SAFE_GUARD_EVM`) need two of three keys to move funds — buyer and seller hold theirs; the node holds an arbiter key used only to execute signed dispute rulings. Fiat never passes through the protocol. The one disclosed exception is `WDK_USDT_EVM`, a server-custodial reference implementation.
- **Open specification.** Any wallet or fintech can implement the Sails spec in any language. The TypeScript reference implementation and the SDK are one implementation, not the specification itself.
- **Identity you own.** A participant is an Ed25519 keypair, not a platform account. You register the same key on any node you use.
- **Verifiable decisions.** Dispute rulings execute only with the assigned arbiter's signature; AI output is advisory and never moves funds.
